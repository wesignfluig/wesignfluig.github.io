Requisitos

O app utilizará uma licença de usuário para o Usuário do Serviço Callback.

É necessário que os endereços do Portal de Assinaturas não possuam restrições de acesso pelo servidor do fluig. Acesse Serviço de Integração Portal de Assinaturas para maiores informações.

Para realizar a instalação do app Wesign no TOTVS Fluig, é necessário a utilização de um usuário com papel de administrador.

O procedimento deve ser realizado pela Central de Componentes, disponível no Painel de Controle. Após o upload do componente EAR, habilite as widgets da para utilização.

Formulários

Nesta estapa será criada uma pasta chamada Wesign em Documentos dentro da pasta raiz do TOTVS fluig. Essa pasta servirá para armazenar os formulários e todas as informações de funcionamento do aplicativo.

O acesso à pasta e aos formulários ficam restritos aos usuários com perfil de Administrador na plataforma.

Os formulários instalados são:

🔹 Parâmetro Gerais (ds_wesign_param_geral)
Formulário responsável por armazenar os parâmetros de integração do app.
🔹 Cadastro de Assinantes (ds_wesign_assinantes)
Formulário responsável por armazenar os dados dos assinantes inseridos através da widget.
🔹 Formulário Auxiliar (ds_form_aux_wesign)
Formulário responsável por registrar cada documento enviado para assinatura, trazendo em cada registro informações relevantes sobre o documento e essenciais para funcionamento correto do app.
🔹 Importador de dados (ds_wesign_param_geral)
Formulário utilizado para importar os dados para a base fluig.

Datasets

Nesta etapa será realizada a instalação dos datasets que farão a integração entre o TOTVS fluig e o Portal de Assinaturas.

Após a instalação, os datasets destacados como Sincronizado poderão ser sincronizados em Painel de Controle > Agendador de Tarefas.

Os datasets instalados são:

🔹 ds_auxiliar_wesign
Possui lógicas para integração com o Portal de Assinaturas e executa os webservices do TOTVS fluig para funcionamento do app na plataforma.
🔹 ds_callback_wesign
É o dataset responsável por atualizar o status do documento/assinante e gerar o manifesto de assinaturas quando o ambiente possui o serviço Callback ativo.
🔹 ds_delete_manifesto_wesign
Responsável por remover o manifesto criado no GED (Documentos) após anexar ao documento original.
🔹 ds_delete_wesign
Cancela o documento no Portal de Assinaturas.
🔹 ds_documents_autocomplete_wesignn (descontinuado)
Lista todos os arquivos disponíveis do GED (Documentos) para envio.
🔹 ds_documents_wesign (descontinuado)
Lista todos os arquivos disponíveis do GED (Documentos) para envio.
🔹 ds_package_wesign (sincronizado)
É o dataset responsável por atualizar o status do documento e gerar o manifesto de assinaturas. Sua lógica verifica se todos os documentos enviados nos últimos 3 meses e que estão status de Pendente foram assinados no Portal de Assinaturas. É executado periodicamente conforme definido em Datasets sincronizados.
🔹 ds_package_completo_wesign (sincronizado)
Possui o mesmo funcionamento do dataset ds_package_wesign, porém verifica todos os documentos com status de Pendente, independente da data de envio. Quanto mais documentos com o status de Pendente, maior será o tempo de execução do dataset.
🔹 ds_reject_document_wesign
Atualizar o status do documento para Rejeitado quando recebe a notificação via serviço Callback.
🔹 ds_signers_wesign (descontinuado)
Lista todos os assinantes cadastrados.
🔹 ds_update_status_wesign
atualiza o status de assinatura do assinante no documento quando o ambiente possui o serviço Callback ativo.
🔹 ds_upload_wesign_manual
É o dataset responsável por realizar o envio do documento para assinatura. É executado após cada envio de documento.
🔹 ds_upload_wesign
Possui o mesmo funcionamento do dataset ds_upload_wesign_manual, porém verifica todos os documentos com status de Enviando que não foram integrados. É executado periodicamente conforme definido em Datasets sincronizados

Serviços

Nesta etapa será realizada a instalação dos serviços utilizados pelo app. Com exceção do serviço wesigner, os demais serviços são webservices da própria plataforma TOTVS fluig.

Os serviços instalados são:

🔹 wesigner
Webservice responsável por realizar a integração entre informações enviadas do TOTVS fluig com o Portal de Assinaturas.
🔹 ECMCardService_wesign
Webservice responsável por realizar operações referentes a formulários.
🔹 ECMCustomFieldsService_wesign (descontinuado)
Webservice responsável por interagir com os campos customizados.
🔹 ECMDocumentService_wesign
Webservice responsável por realizar operações referentes a documentos.
🔹 ECMFolderService_wesign
Webservice responsável por realizar operações referentes a pastas.
🔹 ECMTokenService_wesign
Webservice responsável por validar o usuário e senha de integração configurados no app.
🔹 ECMWorkflowEngineService_wesign (descontinuado)
Webservice responsável por realizar operações referentes a workflow no fluig. Pode ser utilizado para movimentar solicitações, entre outros recursos.

Feita a instalação, eles poderão ser encontrados em: Painel de Controle > Desenvolvimento > Serviços

Campo customizado

Nesta etapa será realizada a instalação do campo customizado que é atualizado a cada alteração de status do documento enviado para assinatura.

Feita a instalação, eles poderão ser encontrados em: Painel de Controle > Personalização > Campos customizados

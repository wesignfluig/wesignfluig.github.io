Requisitos

Para realizar a instalação do app Wesign no TOTVS Fluig, é necessário a utilização de um usuário com papel de administrador.

O procedimento deve ser realizado pela Central de Componentes, disponível no Painel de Controle. Após o upload do componente EAR, habilite as widgets da para utilização.

O app utilizará uma licença de usuário para executar atualizações no documento via serviço de Callback. Acesse a documentação da TOTVS para maiores informações: Como expor dados em ambientes públicos

Formulários

Durante a instalação, será criada uma pasta chamada Wesign em Documentos dentro da pasta raiz do fluig. Essa pasta servirá para armazenar os formulários e todas as informações de funcionamento do aplicativo.

Os formulários instalados são:

  • Parâmetro gerais

    Formulário responsável por armazenar os parâmetros do app. Ele será atualizado conforme a instalação é realizada.

    Dataset do formulário: ds_wesign_param_geral

  • Cadastro de assinantes

    Formulário responsável por armazenar os dados dos assinantes inseridos através da widget.

    Dataset do formulário: ds_wesign_assinantes

  • Formulário Auxiliar

    Formulário responsável por registrar cada documento enviado para assinatura, trazendo em cada registro informações relevantes sobre o documento enviado. Este formulário não será acessado de forma direta pelo usuário.

    Dataset do formulário: ds_form_aux_wesign

  • Importador de dados*

    Formulário utilizado para importar os dados para a base fluig.

    *Este formulário está presente apenas na versão V3.1. Para as demais versões, sua utilização foi descontinuada.

Datasets

Esta etapa é responsável por realizar a instalação dos datasets que farão a integração entre o fluig e o Portal de Assinaturas Wesign.

Os datasets instalados são:

  • ds_auxiliar_wesign: possui lógicas para integração com o Portal de Assinaturas e executa os webservices do TOTVS fluig para funcionamento do app na plataforma.

  • ds_callback_wesign: faz o download do manifesto e anexa no arquivo automaticamente quando o cliente possui "Callback" ativo no ambiente.

  • ds_delete_manifesto_wesign: responsável por remover o manifesto criado no GED (Documentos) após anexar ao documento original.

  • ds_delete_wesign: cancela o documento no Portal de Assinaturas.

  • ds_documents_autocomplete_wesign*: lista todos os arquivos disponíveis do GED (Documentos) para envio.

  • ds_documents_wesign*: lista todos os arquivos disponíveis do GED (Documentos) para envio.

  • ds_package_wesign: verifica todos os documentos (período de 6 meses) com status de Pendente se foram assinados no Portal de Assinaturas. É executado periodicamente conforme definido em Painel de Controle > Agendador de Tarefas. Por padrão, é executado uma vez ao dia.

  • ds_package_total_wesign: possui o mesmo funcionamento do dataset ds_package_wesign, porém verifica todos os documentos com status de Pendente. Quanto mais documentos com o status de Pendente, maior será o tempo de execução do dataset. Não recomendamos a execução diariamente deste dataset, apenas para casos específicos.

  • ds_reject_document_wesign: atualizar o status do documento para "Rejeitado".

  • ds_signers_wesign*: lista todos os assinantes cadastrados.

  • ds_update_status_wesign: atualiza os status de assinatura do assinante no Quadro de Status (quando "Callback" disponível).

  • ds_upload_wesign_manual: envia os documentos para assinatura. É executado após cada envio de documento.

  • ds_upload_wesign: lista todos os documentos do formulário auxiliar que estão pendentes de envio e envia para a Certisign.

Após a instalação, os datasets marcados como "Sincronizado" serão criados no "Agendador de tarefas" do fluig. Por padrão serão executados uma ver por dia, podendo ser alterado. Para visualizar os datasets no "Agendador de tarefas", basta acessar: Painel de Controle > Parâmetros Técnicos > Agendador de tarefas

Serviços

Nesta etapa será realizada a instalação dos serviços utilizados pelo App:

  • ECMCardService_Vertsign: Webservice responsável por realizar operações referentes a formulários no fluig.
  • ECMCustomFieldsService_Vertsign: Webservice responsável por interagir com os campos customizados do fluig.
  • ECMDocumentService_Vertsign: Webservice responsável por realizar operações referentes a documentos do fluig.
  • ECMFolderService_Vertsign: Webservice responsável por realizar operações referentes a pastas no fluig.
  • ECMTokenService_Vertsign: Webservice responsável por interagir com os token's do fluig. Pode ser utilizado para pesquisar e validar os token's existentes.
  • ECMWorkflowEngineService_Vertsign: Webservice responsável por realizar operações referentes a workflow no fluig. Pode ser utilizado para movimentar solicitações, entre outros recursos.

Feita a instalação dos serviços, eles poderão ser encontrados em: Painel de Controle > Desenvolvimento > Serviços

Campo customizado

Nesta etapa da instalação será instalado o campo customizado que é atualizado a cada alteração de status do documento enviado para assinatura.

Após a instalação, para visualizar o campo customizado basta acessar:

Painel de Controle > Personalização > Campos customizados


Observação

Para fins de testes e desenvolvimentos de BPM (vide tópico Integração com BPM), o app Vertsign poderá ser instalado no ambiente de homologação/testes do fluig desde que este esteja direcionado para o mesmo License Server do ambiente de produção fluig.

Vale ressaltar que é necessário um Token de homologação para o Portal de Assinaturas (vide tópico Campos em Configuração).

Atenção!

Caso algum erro tenha ocorrido na instalação, consulte o FAQ.

Atualização

A atualização dos formulários e dos datasets é feita pela widget Instalação e Configuração.

Para clientes que adquiriram a versão 1.0.0 da Vertsign a atualização dos formulários e datasets estará disponível. Para utilizar a versão 1.1.0, é necessário realizar as atualizações. Feita a atualização, as widgets serão liberadas para serem utilizadas e os registros da versão anterior serão mantidos.
